# 拡張と検証・受入基準

## Manifest V3

`manifest_version: 3`。静的content_scriptsを `https://www.kanjipedia.jp/kanji/*` に限定し、さらに実行時に `/kanji/[0-9]{10}` の形式を確認する。`document_idle`、全フレーム注入なし。tabs・scripting・storage・追加host_permissionsは要件がなければ付けない。

第一候補は、収集したJSONからビルド時にデータJSを生成し、content scriptより先に同じisolated worldへ読み込む方式。JSONを原本とし、生成JSで安全なJSONシリアライズを使いeval等を使わない。この方式ならJSONをページへ公開するweb_accessible_resourcesとservice workerは不要。

辞書サイズが大きくJSON読込を選ぶ場合は、公式のcontent scripts資料を再確認して `runtime.getURL` とweb_accessible_resourcesを必要なデータ・サイトだけに限定する。代替としてservice worker経由で同梱JSONを読む場合は、ワーカー再起動、メッセージ応答、サイズをテストする。いずれもサイト検索や外部辞書への通信を行わない。

参考: https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts

## 下つきの照合・書換え

「下つき」見出しの対応領域だけを扱う。括弧の内側を区切らない走査で語と読みの範囲を取り、複数読み・注記を含むfixtureを用意する。語と読みを解釈できない部分はそのまま残す。

正規化した表記で候補を取り、下つきに読みがある場合は読みも一致する候補だけに絞る。読みが一致しなければ、表記候補が1つでもリンク化しない。読みを取得できない場合は、その語の候補が単一URLに一意に定まるときだけ採用する。同一表記・同一読みで異なるURLが残る場合も原文を保つ。

テキストノードの範囲をDOM Range等でアンカーに包み、読み・中点・注記・既存要素・既存イベントを保つ。ページ全体のinnerHTML再代入や正規表現によるHTML置換を行わない。既存aの内部と既に補完した範囲を除外し、再実行で重複リンクを作らない。未知の入れ子構造は書換えない。

リンク先は検証済みpathから同一オリジンURLを構築する。生成aに外部HTMLを流し込まない。通常の同一タブ遷移、キーボードフォーカス、既存の文字色・装飾との整合を確認する。候補がない場合の検索ボタン等は追加しない。

初回DOM処理で十分なら監視を置かない。実測で遅延描画が必要なら監視を対象領域へ絞り、自己変更によるループを防ぎ、不要時は切断する。領域がないページはエラーなしで終了する。

## テスト計画

自動テストは通常ネットワークなしで実行する。HTTP、時計、待機、乱数を差し替え、実時間待ちなしでレート制限を検証する。導入した実装のテスト・buildコマンドをpackage.jsonに用意し、ロックファイルを保存する。

| 対象 | 必須ケース・観測結果 |
| --- | --- |
| HTML抽出 | br/spanでの見出し・読み分離、sup、囲み、異表記、中点の保留、外字保留、0件、構造崩れ、別検索条件、無関係リンク除外 |
| ページネーション | page省略=内部1、末尾リンク、途中10ページまでの表示、最終端数、範囲外、同じページ返却、件数変動、500本文0 byteを0件としない |
| データ | 愛着2URLの保持、同一候補重複統合、同表記同読別URL、旧字体とIVS保持、合成濁点、危険なURL、安定出力とハッシュ、スキーマ不一致 |
| HTTP制御 | 同時実行1と二重起動拒否、最小間隔、日次上限、全リトライ計数、タイムアウト、Retry-After秒／日時／不正値、403、200のブロック画面、リダイレクト制限、連続失敗停止 |
| 永続化 | 取得後／解析後／done記録前の中断、途中書込、inflight復旧、再開で正常ページ再取得なし、再開で冷却期間維持、古い完成JSONを途中結果で上書きしない |
| DOM書換え | 語＋読み一致のみ変更、白亜と白亜紀の誤一致なし、複数読み、未登録語保持、既存a・入れ子・下つきなし、2回実行、他の欄のDOMと表示保持 |

ブラウザ自動テストはChrome/Chromiumで拡張を実際にロードし、ローカルfixtureまたは通信を遮断したルーティングで対象URLのHTMLを返す。拡張なしのページと比較して拡張由来の追加HTTPが0件であることを確認する。データサイズ、初期化時間、処理時間を測り、辞書読込・DOM処理の重複がないことを確認する。

Chromeの開発者モードから展開済み拡張を読み込み、最終的に実サイトの亜と追加数ページで目視する。手動確認をしていない場合は未実行と明記する。実機確認のために全個別記事を巡回しない。

## テストの品質

期待値の独立性・異常系・保存障害の具体的な判断と全体点検の結果は [テストの方針と全体点検](../../../../docs/testing.md) を参照する。

- リンクの期待値は確認済みの文字列・URLで指定し、本番の候補選択関数で計算しない。辞書の安定性の比較だけで内容の正しさを代用しない。
- 異常系では停止理由・終了コードと、送信されなかった要求や保持された保存状態を確かめる。条件を列挙する場合は入力を識別できる名前や診断を付ける。
- 保存状態を用意する復元試験と、保存境界でI/O障害を起こす試験を区別する。同じ状態に違う中断段階名を付けたり、無関係なtmpファイルを置くだけで原子性を検証済みにしない。
- ブラウザの追加HTTPはユーザー操作前の要求全体で比較する。遷移先URLを一律除外すると、余計な先読み通信を見逃す。操作後は同一タブの遷移も確認する。
- 時計・待機・HTTPを制御し、テスト専用の一時ファイルとプロファイルを失敗時も後始末する。重要なテストの検出力が疑わしい場合は、別コピーへの限定した不具合注入で確認し、測っていない網羅率やTDD実践を主張しない。

## 受入基準

1. 検証した白亜の見出し・読み・URLを収集JSONへ収録すると、亜の下つき「白亜」からその既存項目に移動できる。他の3語は対応データがある場合だけ同じルールでリンク化される。
2. 既存項目がない／収集されていない語、読み不一致、曖昧候補は原文を保持する。未登録を不存在と誤表示しない。
3. 下つき以外の欄、読み・区切り・レイアウトを保ち、二重注入や下つきがないページでも壊れない。
4. MV3拡張が警告・例外なく読み込める。拡張自身がサイト検索、外部取得、閲覧履歴送信をしない。
5. 収集が設定レート・上限を守り、失敗と中断から再開でき、成功ページを再取得しない。429/403/robots拒否の停止をテストできる。
6. 生成辞書がスキーマ、安定性、URL安全性、重複保持を満たす。全対象接頭辞のページと件数が整合し、未確認接頭辞・欠落ページ・解析不能が報告される。
7. completeは対象範囲の未解決ページが0のときに限る。解析保留があれば対応表の範囲制約を明示し、誤って全語対応と表示しない。
8. 実行方法、再開、データ更新、テスト、Chrome導入、データ範囲と出典、公開判断の未解決事項が記録される。JSONやHTMLを公開する前に利用条件と配布根拠を確認する。

上記はSkill作成時の実装・検証計画。現在の実装と実行済みの検証は [実装・受入検証](../../../../docs/verification.md) を参照する。未実施の実サイト手動確認と、実行済みの自動検証を区別する。
